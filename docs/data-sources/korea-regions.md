# 홈 날씨 지역 목록 (시·도 → 시·군·구 → 읍·면·동)

홈 날씨에서 "지역 직접 고르기"로 고르는 전국 행정구역과 대표 좌표다. 앱 안에
`data/weather/src/main/assets/weather/korea_regions.csv`(판 `2026-07`)로 들어 있고, 네트워크 없이 읽는다.
앱을 새로 내지 않아도 naurylab.com에 올린 새 목록을 받아 쓸 수 있다(아래 "웹에서 새 목록 받기").

## 출처

| 파일 | `기상청41_단기예보 조회서비스_오픈API활용가이드_2609.zip` 안의 `기상청41_단기예보 조회서비스_오픈API활용가이드_격자_위경도(2607).xlsx` (시트 `최종 업데이트 파일_20260701`) |

## 바꾼 것

`scripts/build-korea-regions.py`로 만든다(openpyxl 필요).

- 칸: `행정구역코드, 그 단계 이름, 위도, 경도[, 시·도 짧은 이름]`. 원본의 경도·위도(초/100)를 소수 넷째 자리(약 10m)로 줄였다.
- 이름은 원본 그대로 둔다(`수원시장안구`). 앱이 화면에 쓸 때 `수원시 장안구`로 띄어 쓴다.
- 시·도 짧은 이름(서울특별시 → 서울, 전남광주통합특별시 → 전남광주)은 스크립트의 표에서 붙인다.
- 좌표가 0인 이어도(해양과학기지) 두 줄은 뺐다.
- 격자 X·Y, 위치 업데이트 날짜 칸은 쓰지 않아 뺐다.

결과: 3,836곳(시·도 16, 시·군·구 256, 읍·면·동 3,564), 약 146KB. APK 안에서는 압축되어 약 58KB(59,272바이트)다.

## 앱에서 쓰는 방법

- 설정(DataStore)에는 고른 지역의 행정구역코드만 저장한다. 좌표는 저장하지 않는다.
- 날씨를 받을 때 고른 지역의 대표 좌표를 소수 둘째 자리(약 1km)로 반올림해 MET Norway에 보낸다.
  기기 위치("현재 위치")는 계속 소수 첫째 자리(약 10km)로 반올림한다. `docs/release/data-safety.md` 참고.
- 예전 버전이 저장한 시·도 이름(`Busan`)은 `WeatherRegionMigration`이 코드로 바꾼다. 2026-07 원본에서
  광주광역시와 전라남도가 전남광주통합특별시로 합쳐져, 광주는 예전 대표 지점(시청)이 있는 `전남광주 서구`로,
  전남은 `전남광주`(무안 도청 지점)로 옮긴다.
- 원본을 새 버전으로 바꾸면 없어진 코드는 위 시·군·구, 시·도로 거슬러 올라가 보여 준다(`KoreaRegionCatalog.resolve`).

## 새 버전으로 바꾸기

1. 위 공공데이터포털 페이지의 참고문서 zip을 받아 격자_위경도 xlsx를 꺼낸다.
2. `python3 scripts/build-korea-regions.py <xlsx> > data/weather/src/main/assets/weather/korea_regions.csv`
   (새 시·도가 생기면 스크립트의 `SHORT_NAMES`에 짧은 이름을 더한다.)
3. `./gradlew :data:weather:testDebugUnitTest`로 목록 검사(`KoreaRegionDatasetTest`)를 돌린다.
4. 이 문서의 파일 이름, 날짜, sha256, 곳 수와 설정 › 정보 출처 문구의 날짜를 고친다.

## 웹에서 새 목록 받기

앱에 넣은 목록보다 새 판이 나오면 앱 업데이트 없이 웹에 올려 바꾼다.

### 올리는 파일

- 안내 파일: `https://naurylab.com/chageun/data/regions/regions.json`

  ```json
  { "schema": 1, "version": "2026-10", "file": "regions-2026-10.csv", "sha256": "<CSV 바이트의 sha256 hex>",
    "rows": 3836, "source": "기상청 단기예보 조회서비스 격자·위경도 (공공데이터포털 15084084), 2026-10-01, 저작자표시",
    "renamedCodes": { "<예전 코드>": "<새 코드>" } }
  ```

- 목록 파일: `https://naurylab.com/chageun/data/regions/<file>`. 앱에 넣은 CSV와 같은 형식(`#` 설명 줄, `코드,이름,위도,경도[,짧은 이름]`)이다.
- `version`은 `YYYY-MM`이다. 글자 순서로 비교하므로 반드시 이 형식을 지킨다.
- `file`은 경로 없는 이름(영문·숫자·`.`·`_`·`-`, `.csv`로 끝남)이어야 한다. 판마다 새 이름을 쓰는 것이 안전하다.
- `sha256`은 소문자 16진수 64자다.
- `renamedCodes`는 코드가 바뀐 동만 적는다. 판을 건너뛴 기기도 있으므로 예전 판들의 바뀐 코드를 모두 쌓아 둔다.
  A→B, B→C처럼 이어지면 앱이 C까지 따라간다.
- `schema`를 2 이상으로 올리면 지금 앱은 그 안내 파일을 무시한다. 칸을 바꿀 때만 올린다.

### 앱이 하는 일

1. 확인 시점: 주 1회 WorkManager 작업(네트워크 연결, 배터리 부족 아님. 네트워크 실패는 1시간부터 늘어나는 간격으로 3번까지 다시),
   지역 고르기 창을 열 때(마지막 확인 뒤 7일이 지났을 때만, 창은 기다리지 않음), 설정 › 날씨 › "지역 목록 업데이트 확인".
2. 안내 파일을 받는다(HTTPS, 10초 제한, 256KB까지). `schema`가 1보다 크면 무시한다.
3. `version`이 지금 쓰는 목록보다 새것일 때만 목록 파일을 받는다(2MB까지).
4. sha256, 줄 수(`rows`), 기존 파서로 읽기, 좌표(위도 33.0~38.7, 경도 124.5~132.0), 코드 10자리·중복 없음,
   모든 시·군·구와 읍·면·동의 윗 지역, 시·도 짧은 이름, 3,000줄 이상을 모두 맞춰 본다.
5. 통과하면 `files/weather/regions/`에 목록 파일, 안내 파일 순으로 임시 파일에 쓰고 이름을 바꿔 저장한다.
   중간에 앱이 꺼져도 예전 목록이나 새 목록 중 하나만 쓰인다. 읽을 때도 sha256을 다시 맞춰 보고, 틀리면 지우고 앱에 넣은 목록으로 돌아간다.
6. 메모리의 목록을 새로 읽어, 앱을 다시 켜지 않아도 지역 고르기 창·홈·설정이 새 목록을 쓴다.
7. 고른 지역과 최근 지역의 코드를 `renamedCodes`로 고친다(판마다 한 번). 고른 지역이 새 목록에 없으면
   위 시·군·구나 시·도의 날씨를 보여 주면서 홈 날씨 줄 아래에 "날씨 지역이 바뀌었어요 · 다시 고르기"를 한 번 띄운다
   (✕로 닫거나 지역을 다시 고르면 사라진다).

어느 단계에서든 실패하면 가진 목록을 그대로 쓰고 앱은 멈추지 않는다. 로그에는 실패 종류(network/invalid)만 남기고
지역 코드는 남기지 않는다. 요청에는 고른 지역·계정·기기 ID가 없다(`docs/release/data-safety.md`).
받은 목록과 안내 파일은 공개 자료라 설정 › 데이터 › 모두 삭제에서도 지우지 않는다.
앱에 넣은 목록을 더 새 판으로 바꿔 앱을 내면(`KoreaRegionCsv.BUNDLED_VERSION`도 함께 고친다) 그보다 옛 받은 목록은 쓰지 않는다.

### 올리기 전 확인

```sh
shasum -a 256 regions-2026-10.csv          # 안내 파일의 sha256
grep -vc '^#' regions-2026-10.csv          # 안내 파일의 rows (빈 줄이 없을 때)
```

목록 파일을 `data/weather/src/main/assets/weather/korea_regions.csv`에 잠시 넣고
`./gradlew :data:weather:testDebugUnitTest --tests '*KoreaRegionDatasetTest*'`로 같은 검사를 돌려 볼 수 있다.
안내 파일은 목록 파일을 올린 뒤 마지막에 바꾼다.
