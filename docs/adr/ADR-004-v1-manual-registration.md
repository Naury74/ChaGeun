# ADR-004 V1은 공식 차량 데이터 없이 수동 등록으로 출시한다

Status: Accepted

## Context

Stage 0 PoC(#8)에서 차량번호로 개별 차량 정보를 받을 수 있는 공공 API를 조사했다. 결과는 아래와 같다.

| API | 신청 방식 | 개별 차량 조회 | 조건 |
|---|---|---|---|
| 국토교통부 자동차종합정보 (data.go.kr 15071233) | LINK, 자동차365 별도 연계 | 가능 (차량번호 + 소유주명) | 소유주 제3자 정보제공 동의 필수, 출처표시·변경금지, 운영 단계 심의승인 |
| 국토교통부 자동차 리콜정보 (15089863) | LINK, 한국교통안전공단 사전협의 | 가능 (차대번호) | 베타 서비스, 제공 여부를 협의로 결정 |
| 공정거래위원회 자동차 리콜정보 (15057410) | LINK | 품목 단위 | 전 부처 리콜 공통 정보 |
| 한국교통안전공단 자동차 검사정보 (15057736) | 일반, 자동승인 | 불가 | 날짜·지역·차종별 검사 통계 |

개별 차량 정보는 모두 별도 연계나 사전협의를 거쳐야 하고, 바로 신청할 수 있는 API는 통계뿐이다. 개인 개발 단계에서 승인 여부와 시점을 예측할 수 없다.

## Decision

- 기획서 Stage 0 Gate("불가할 경우 수동등록 V1로 전환")에 따라 V1은 수동 등록으로 출시한다.
- 차량 정보, 주행거리, 다음 검사일은 사용자가 입력하고 화면에 `직접 입력` 출처를 표시한다.
- 리콜은 대상 여부를 판단하지 않는다. `리콜 없음`으로 표시하지 않고 자동차리콜센터 공식 사이트로 연결한다.
- 자동차종합정보 API는 자동차365로 신청을 진행하고, 승인되면 ADR-002 구조(Worker 프록시, Lookup Adapter, `직접 입력`과 구분되는 `공식` 출처)로 연동한다.
- 통계 API(15057736)는 개별 차량 상태 판단에 쓸 수 없어 연동하지 않는다.

## Consequences

- 앱은 네트워크 권한 없이 동작하고, 공공 API Key와 서버 운영 비용이 V1에 없다.
- 등록 단계가 길어진다. 모르는 항목은 건너뛸 수 있게 하고 정보가 부족한 항목은 `정상`으로 표시하지 않는 기존 규칙으로 보완한다.
- 검사 기한과 알림은 사용자가 입력한 날짜에 의존한다. 검사 완료 처리 시 다음 검사일을 제안해 입력 부담을 줄인다.
- `InspectionSource.Official`, `RegistrationMode.Auto`, Lookup Adapter 자리는 연동 시점을 위해 유지한다.

## Alternatives considered

- **통계 API로 대체**: 내 차의 검사 상태나 이력을 알 수 없어 기능 가치가 없다.
- **민간 차량 이력 서비스**: 유료 B2B 계약이 필요해 개인 프로젝트 범위를 벗어난다.
- **승인될 때까지 출시 보류**: 공식 데이터 없이도 정비·기록·알림·AI 공유의 핵심 가치는 완결된다.
