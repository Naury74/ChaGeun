# ADR-006 개발자 비용 없는 백업: ZIP과 사용자 Google 드라이브

Status: Accepted (ADR-005의 저장소 결정을 대체한다)

## Context

ADR-005는 백업 파일을 Firebase Cloud Storage에, 목록을 Firestore에 두기로 했다. Storage는 Blaze(종량제) 요금제와 결제 계정이 필요하고, 스토어에 배포하면 사용자 수와 사진 양에 따라 개발자에게 비용이 생길 수 있다. 차근은 개발자 비용이 절대 생기지 않아야 한다.

## Decision

- Firebase는 무료 요금제(Spark)로 두고 **Authentication(이메일·Google)**, Analytics, Crashlytics만 쓴다. 결제 계정을 연결하지 않으므로 비용이 청구될 수 없다.
- Firestore와 Cloud Storage는 쓰지 않는다. 규칙 파일(`firebase/`)도 지운다.
- 기기 변경은 두 가지로 한다.
  - ZIP 파일: 기존 내보내기·가져오기를 공유 창과 온보딩 "백업 파일로 시작하기"로 다듬는다. 서버를 거치지 않는다.
  - 사용자 본인 Google 드라이브의 앱 전용 숨김 폴더(`appDataFolder`, 범위 `drive.appdata`): 사용자가 켤 때만 쓴다. 용량은 사용자 드라이브에서 쓰고, 차근 운영자는 파일에 접근할 수 없다.
- 드라이브 백업의 흐름(지금 백업, 목록, 최근 5개 보관, 주 1회 자동 백업, 복원 미리보기)은 ADR-005 구현을 그대로 쓰고 원격 저장소만 바꾼다(`CloudBackupRemote`).
- 계정은 이메일을 아이디로 쓰고, 이메일 인증을 마쳐야 가입이 끝난다. 인증 전에는 인증 안내 화면만 보인다. 계정 삭제는 Firebase 사용자만 지운다. 드라이브 백업은 사용자 드라이브에 남고, 드라이브 설정에서 지울 수 있다고 안내한다.

## Consequences

- 개발자 비용이 0원으로 고정된다. 운영자가 사용자 백업을 보관하지 않아 개인정보 범위도 줄어든다.
- 드라이브 백업에는 Google Cloud 콘솔에서 Drive API 사용 설정과 OAuth 동의 화면(무료)이 필요하다. 출시 전에 Google 앱 검토를 거칠 수 있다.
- 이메일 계정만 있는 사용자도 드라이브 백업을 쓰려면 Google 계정 권한을 따로 허용해야 한다.
- 인증하지 않고 떠난 가입 시도는 Firebase에 인증 전 사용자로 남는다. 같은 이메일로 다시 로그인하면 인증 메일을 다시 받을 수 있고, 인증 화면에서 "다른 이메일로 가입하기"를 누르면 지운다.

## Alternatives considered

- **Firebase Storage 무료 사용량 안에서 쓰기**: Blaze 요금제가 필요하고 상한을 강제할 수 없어 비용 0을 보장하지 못한다.
- **Firestore에만 저장(Spark)**: 문서 크기 1MB 제한으로 사진을 담을 수 없고, 무료 한도를 넘으면 기능이 멈춘다.
- **ZIP만 제공**: 비용은 없지만 자동 백업이 없다. ZIP은 기본으로 두고 드라이브를 선택 기능으로 더한다.
